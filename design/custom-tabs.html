How it works

Claude builds it once. The island runs it.

Making the tab is the only step that uses Claude. After that the island fetches the data and draws it itself, so a custom tab is as fast and light as a built-in one, and it costs nothing to keep open.

The key idea

Claude writes a recipe, not code

The tab is a small JSON “recipe”: where the data comes from, how to read it, which of the island’s widgets show it, and what counts as news. The island already knows how to draw and animate every widget.


    

      
cloud_downloadsource
A web address the island reads every N seconds (or a Claude refresh, or a local command; see below).

      
filter_altitems + fields
Which part of the reply is the list, and what each field means (“home”, “score”, “minute”). Claude works this out by reading a real reply.

      
dashboardview
Widgets from the kit: list, score row, big number, chart, cards, table, ring, countdown. Nothing else can be drawn, so every custom tab looks like the island.

      
notifications_activealerts
When to tell you, even with the island closed: “a score changed”, “price moved 5%”, “PR approved”.

    

  


  
Why a recipe

  
Four reasons it beats generating code

  
Letting Claude write C# for each tab sounds more powerful, but it would make the app slower, riskier and harder to trust.

  

    
paletteIt looks and moves like the island
Same fonts, colours, springs and Bloub. A custom tab can’t look “off”, because it’s drawn by the same code as Servers or Tasks.

    
speedIt stays fast
The renderer only redraws what changed, and widgets were built for that. A generated tab keeps the 20× performance work intact.

    
shieldIt’s safe
A recipe is data. It can’t run code, read your files or open other sites. The source it uses is shown to you before the tab is added.

    
ios_shareIt’s easy to change and share
“Only the Premier League” edits the recipe. A recipe is one small file, so tabs can be exported, shared with friends, or picked from a gallery later.

  


  
The widget kit

  
What a recipe can use

  
Eight widgets cover almost every “show me X” request. Claude chooses and combines them; the island draws them natively and animates every change.

  


  
Where data comes from

  
Three kinds of source

  
Claude prefers the cheapest one that works.

  

    
publicA web feed
Most things have one: scores, prices, weather, transit, GitHub. The island reads it directly every few seconds or minutes.
free to runlive

    
smart_toyA Claude refresh
For sites without a feed (“today’s menu at my gym”): Claude reads the page and fills the recipe, every 30–60 minutes at most.
uses your Claude usageslow

    
terminalYour computer
A command or file you approve: “my Docker containers”, “tests in this repo”, “disk space”. Nothing leaves your PC.
privatefree to run

Build plan

  
How I’d build it, step by step

  
Each phase ships something usable on its own, so we can stop and judge before the next.

  

    
Phase 1the engine
Recipes and the widget kit
The recipe format, a reader for web feeds, and the eight widgets with their animations (rolling numbers, gliding rows). Four hand-written recipes prove it: football, crypto, weather, GitHub PRs.
  • Custom tabs live in %APPDATA%\Island\tabs\*.json
  • Showcase mode gets sample custom tabs with scripted data

    
Phase 2the brain
Claude writes recipes
A headless Claude run with the recipe format and web search: it finds a source, reads a real reply, writes the recipe, and the island checks it (does it fetch? do the fields fill?) and sends it back to Claude to fix if not.

    
Phase 3the experience
The “+” tab, preview and refine
Everything in the demo above: the orb Bloub thinking with live steps, the shimmering preview filling with real data, “Change something”, and the tab flying into the bar.

    
Phase 4the magic
Live activities and sharing
Alerts from custom tabs in the closed island (the goal pill), Claude-refresh and local-command sources, export/import of recipes.
